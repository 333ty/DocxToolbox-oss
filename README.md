# Word 批处理工具箱

批量清理 Word 文档（`.docx`）的**页眉页脚、末尾空白节、文档属性**，并可**清除隐私残留、接受修订与清除批注、清理未引用媒体、按哈希删除指定图片**（支持一次给多个哈希），还能**按关键词检测来源水印并清掉水印对象**（可选本机 OCR 识别图片里的文字），以及**按正则批量重命名文件名**。程序直接改写 OOXML 包内部结构，**不需要本机安装 Microsoft Word**。

同一个 `Word 批处理工具箱.exe` 有两种用法：

| 启动方式 | 行为 |
| --- | --- |
| 双击（不带参数） | 打开图形界面 |
| 带参数运行 | 命令行模式，适合批量处理和脚本 |

> ⚠️ 处理是**就地覆盖原文件**，没有备份、没有撤销。批量操作前请先自行复制文档，或先用 `--dry-run` 预览。
>
> 每次写入都走「临时文件 → OpenXML 校验 → 原子替换」：**校验错误变多、文件被占用、只读、损坏时会直接放弃，原文件保持原样**（详见下文「写入方式」）。

> **免责声明 / 使用边界**：本工具仅用于管理**你自己拥有或有权处理**的文档（如清理自己文档的元数据、编辑痕迹、追踪图片与来源水印）。使用者需自行确保对所处理的文档拥有合法权利；请勿将本工具用于去除他人仍享有权利内容的版权标识、以规避授权或传播限制。作者不对任何使用方式及其后果承担责任。本工具不预置任何品牌词，水印清理的触发词完全由使用者自行提供。

## 图形界面

- **选择文件（可多选）** 或 **选择文件夹（含子文件夹）**：文件夹会递归收集其中的 `.docx`，自动跳过 `~$` 开头的 Word 临时文件。
- 勾选要执行的清理项（页眉页脚 / 末尾空白节 / 属性信息 / 清除隐私残留 / **接受修订、清除批注** / 清理未引用媒体 / 按哈希删图），点「开始处理」，下方日志区逐文件输出 `[成功]` / `[跳过]` / `[异常]`。
- **接受修订、清除批注**：把 `ins` / `del` / 移动 / 格式修订等痕迹抹掉（`ins` 的内容保留、`del` 的内容真的删除，等价于「接受所有修订」），批注锚点与 `comments.xml` 部件一并清除。**会改变文档可见内容**，勾选前请先想清楚。
- 处理在后台线程跑：上方进度条显示「已完成 / 总数」，随时可以点「取消」；当前文件处理完就停，处理过程中窗口不允许关闭。
- **探测分节结构**：只读分析，逐节列出块范围、段落数、表格数、页眉页脚引用和「有内容 / 空白」，最后给出「末尾有几个空白节、会被清掉几个」的结论——建议先探测，再决定要不要删。同样是后台执行，不卡界面。
- **计算参考哈希**：挑一张图片算出哈希填进输入框；**哈希算法**下拉支持 MD5 / SHA1 / SHA256。哈希框可以放多个值，用空格、逗号或换行分隔。
- 哈希值和算法会自动记住，存在 `%AppData%\DocxToolbox\settings.json`，下次打开自动回填（旧版的 `%AppData%\WordTool\` 会在首次启动时读一次，之后写入新路径）。
- **重命名文件…**：填「匹配正则」和「替换为」（可用 `$1` 引用分组），点按钮会先弹**预览**，逐条列出「原文件名 → 新文件名」和处置状态，可单条勾选，确认后才真的改名。正则只作用于主文件名，`.docx` 扩展名不会被碰；目标已存在、替换后为空、含非法字符的会标红并自动跳过。规则和「忽略大小写」也会记住。
- **去 +/空格**：一键把内置规则 `[+\s＋]+` 填进输入框并立刻弹预览，专治「`1.1+标题文字…`」「` 前面多个空格`」这类从网上下来的文件名。它只删 `+` 和空白，不做其他改动；同样要过预览确认。
- **水印检测**：填触发词（自己定义，多个词用逗号分隔），勾上后处理时先检查文档里有没有这些字。命中才动手，**只删水印对象**——VML 艺术字水印、`alt`/`descr` 里带关键词的 logo 图、以及 0.05pt 这种看不见的埋点图；**正文里的正常插图不动**。勾「命中删全部图」才会连插图一起删（会毁文档，慎用）。
- **OCR 目录**：填本机 `ppocr.exe` 所在目录（PaddleOCR 编译版，**程序不附带，需自行准备**），程序会把文档里的位图抽到临时目录，一次进程批量识别，**图片里的文字命中触发词才删那张图**。留空＝不做 OCR，只按文字和图形属性判断。识别 20 张图约 14 秒，每个文档默认最多识别 60 张。

## 命令行

### 用法

```
Word 批处理工具箱.exe <路径...> [选项]
```

`<路径...>` 可以是一个或多个 `.docx` 文件，也可以是文件夹（**默认递归子文件夹**）。长选项不区分大小写，短选项区分大小写（`-a` 是全部清理，`-A` 是分节探测）。也可以写成 `--algo=SHA256` 这种 `=` 形式。

### 选项

| 选项 | 说明 |
| --- | --- |
| `-hf`, `--headers` | 删除页眉页脚 |
| `-ls`, `--last-section` | 从末尾往前删空白节（只删没有实质内容的节，遇到有内容的就停） |
| `--force` | 配合 `--last-section`：不看空白判断，强制删掉最末尾那一节（连内容一起删，旧行为） |
| `-p`, `--props` | 删除文档属性（作者、标题、公司、时间戳、自定义属性、缩略图） |
| `-pr`, `--privacy` | 清除隐私残留：rsid 编辑会话 ID、`customXml` 存储、`docVars`、附加模板路径、外部超链接（保留文字） |
| `-tc`, `--track-changes` | **接受所有修订并清除批注**：`ins`/`moveTo` 内容保留、`del`/`moveFrom` 内容删除，删除格式修订与批注锚点及 `comments.xml` 部件（**会改变文档可见内容**，独立选项，不包含在 `--all` 里） |
| `-wm`, `--watermark <词>` | **水印/来源检测**：命中指定文字才清理水印对象。多个词用逗号/分号/顿号分隔，可重复给；触发词由用户自定，程序不预置 |
| `--wm-drop-all-images` | 配合 `--watermark`：命中就连正文插图一起删（激进，会毁掉试卷插图和公式图） |
| `--ocr <目录>` | 配合 `--watermark`：对文档图片做文字识别，`<目录>` 是本机 `ppocr.exe` 所在目录 |
| `--ocr-max <数量>` | 每个文档最多识别多少张图，`0` 表示不限（默认 60） |
| `-oc`, `--orphans` | 清理没人引用的媒体和包内失效条目（省体积） |
| `-ih`, `--image-hash <哈希>` | 删除哈希匹配的图片，可重复给出，也支持一个参数里用逗号/分号分隔多个 |
| `--image-hash-file <文件>` | 从清单文件读哈希，一行一个，`#` 开头为注释 |
| `-al`, `--algo <算法>` | 图片哈希算法：`MD5`（默认）/ `SHA1` / `SHA256` |
| `-a`, `--all` | 等于 `--headers --last-section --props`（不含隐私与媒体清理） |
| `-rn`, `--rename <正则>` | 按正则重命名文件名，只作用于主文件名，扩展名保留 |
| `-rt`, `--rename-to <替换>` | 替换模板，可用 `$1` 引用分组；省略表示删掉匹配到的部分 |
| `--rename-ignore-case` | 重命名匹配时忽略大小写 |
| `-cn`, `--clean-name` | 内置快捷规则：去掉文件名里的 `+` 和各种空格（含全角空格、全角 `＋`）。等价于 `--rename='[+\s＋]+'`；同时写了 `--rename` 时以 `--rename` 为准 |
| `-A`, `--analyze` | 探测分节结构（只读，可与清理项同时使用） |
| `-vd`, `--validate` | 统计 OpenXML 校验错误数（只读，0 表示结构合法；有错误时退出码为 1，适合做回归） |
| `--hash-file <图片>` | 计算并打印一个图片文件的哈希值（只读） |
| `-n`, `--dry-run` | 只报告将要做什么，不修改文件 |
| `--no-recurse` | 扫描文件夹时不进入子文件夹 |
| `-q`, `--quiet` | 只输出错误和最终汇总 |
| `-h`, `--help` | 显示帮助 |
| `--version` | 显示版本号 |

### 示例

```powershell
# 1) 先干跑，看看会对哪些文件做什么（不修改任何文件）
.\Word 批处理工具箱.exe D:\docs --all -n

# 2) 批量删除页眉页脚、末尾空白节、文档属性（递归子文件夹）
.\Word 批处理工具箱.exe D:\docs --all

# 3) 只处理一个文件，只删页眉页脚和文档属性
.\Word 批处理工具箱.exe D:\docs\合同.docx --headers --props

# 3b) 把审阅痕迹的指纹也清掉，顺手收掉多余媒体
.\Word 批处理工具箱.exe D:\docs --privacy --orphans

# 3c) 连修订痕迹和批注（作者、时间）一起清掉——会接受所有修订，先干跑确认
.\Word 批处理工具箱.exe D:\docs --privacy --track-changes -n
.\Word 批处理工具箱.exe D:\docs --privacy --track-changes

# 4) 先算出一张图片的 SHA256 哈希，再用它删掉文档里的同款图片
.\Word 批处理工具箱.exe --hash-file logo.png --algo SHA256
.\Word 批处理工具箱.exe D:\docs --image-hash 74d00b80... --algo SHA256

# 4b) 一次删掉多种图片：重复给参数，或者写成清单文件
.\Word 批处理工具箱.exe D:\docs --image-hash <哈希1> --image-hash <哈希2>
.\Word 批处理工具箱.exe D:\docs --image-hash-file hashes.txt --algo SHA256

# 5) 只看分节结构，不做任何修改
.\Word 批处理工具箱.exe D:\docs --analyze

# 5b) 不管末尾那节有没有内容，硬删（慎用，会一起删正文）
.\Word 批处理工具箱.exe D:\docs\旧的.docx --last-section --force

# 6) 多个文件、安静模式
.\Word 批处理工具箱.exe a.docx b.docx --props -q

# 7) 把文件名里的 (1) (2) 换成 _v1 _v2：先干跑看预览，确认无误再实跑
.\Word 批处理工具箱.exe D:\docs --rename='\s*\((\d+)\)\s*$' --rename-to='_v$1' -n
.\Word 批处理工具箱.exe D:\docs --rename='\s*\((\d+)\)\s*$' --rename-to='_v$1'

# 7b) 只删掉匹配到的部分（不给 --rename-to，等于替换成空）
.\Word 批处理工具箱.exe D:\docs --rename='【复印件】' -n

# 7c) 一键去掉文件名里的 + 和各种空格（含全角空格、全角 ＋）：内置规则，不用写正则
.\Word 批处理工具箱.exe D:\docs --clean-name -n
.\Word 批处理工具箱.exe D:\docs --clean-name

# 8) 检出指定来源词才清掉水印对象（触发词自定）；先干跑看哪些文档会命中
.\Word 批处理工具箱.exe D:\docs --watermark=某公司,example.com -n
.\Word 批处理工具箱.exe D:\docs --watermark=某公司,example.com

# 8b) 连图片里的文字也认（本机 ppocr 目录），只删识别到关键词的那张图
.\Word 批处理工具箱.exe D:\docs --watermark=某公司 --ocr D:\software\ppocr
```

> ⚠️ 替换模板里的 `$1` 在 PowerShell **双引号**里会被当成变量展开成空，请一律用**单引号**写正则和替换模板，或者写成 ``--rename-to=`_v`$1`` 转义。正则以 `-` 开头时，要写成 `--rename='-?\d+'` 或 `--rename=-?\d+` 这种形式，否则会被当成选项。

### 输出与退出码

每个文件输出一行结果，最后是汇总行：

```
待处理文件: 3 个
[成功] 删除页眉页脚: D:\docs\a.docx
[跳过] 文档仅有一节，无法删除: D:\docs\b.docx
[异常] 处理失败: D:\docs\c.docx - 文件被占用
------ 完成: 共 3 个文件，成功 2，失败 1 ------
```

| 退出码 | 含义 |
| --- | --- |
| `0` | 全部成功 |
| `1` | 有文件处理失败，或没找到任何可处理的 .docx |
| `2` | 参数错误（未知选项、缺少参数值、非法哈希、没有指定任何操作等） |

### 在 PowerShell 里运行

程序是 Windows 图形子系统程序（双击不弹黑框），命令行输出靠附加到父控制台，PowerShell 也**不会等待**这类程序结束。所以不要直接运行、也不要用 `>` 重定向——实测那样只会得到空输出。要把输出接进管道，或者用 `Start-Process -Wait`：

```powershell
# 方式一：管道（推荐）
.\Word 批处理工具箱.exe D:\docs --all | Out-Host

# 方式二：等待结束并捕获退出码
$p = Start-Process -FilePath '.\Word 批处理工具箱.exe' -ArgumentList 'D:\docs', '--all' -Wait -PassThru
$p.ExitCode

# 方式三：存成日志（同时还能在控制台看到）
.\Word 批处理工具箱.exe D:\docs --all | Tee-Object -FilePath process.log

# 方式四：只要日志文件
.\Word 批处理工具箱.exe D:\docs --all | Out-File -Encoding utf8 process.log
```

## 各项清理都做了什么

| 清理项 | 具体行为 |
| --- | --- |
| 删除页眉页脚 | 删除文档中所有页眉、页脚部件，并清除各分节里的页眉页脚引用 |
| 删除末尾空白节 | 从最后一个节往前扫，连着删掉**没有实质内容**的节（空段落不算内容；文字、表格、图片、批注、脚注、域都算），一遇到有内容的节立刻停手。每删一节都把前一节的页面设置（纸张、页边距、页眉页脚引用）提升到文档末尾，正文和版式不受影响。**文档只有一节时自动跳过并提示**；末尾那节有内容时输出 `[跳过] 最后一节还有内容`，确认要删得显式加 `--force` |
| 删除属性信息 | 清空核心属性（作者、最后修改者、标题、主题、关键词、备注、类别、内容状态、版本、修订号、创建/修改/打印时间），并删除扩展属性部件、自定义属性部件（`docProps/custom.xml`）和缩略图（`docProps/thumbnail.jpeg`） |
| 清除隐私残留 | 删掉正文/页眉/页脚上的 `rsid` 编辑会话 ID（能反推编辑历史）、`settings.xml` 里的 `rsids` 与 `docVars`、附加模板路径、`customXml` 数据存储（顺带摘掉内容控件的数据绑定）、外部超链接的指向（保留文字与格式） |
| 接受修订、清除批注 | 删除 `w:del`/`w:cellDel`/`w:cellMerge`/移动标记/格式修订（`rPrChange` 等）/`customXml` 修订，解包 `w:ins`/`w:moveTo`/`w:cellIns` 保留内容，剥离 `author`/`date`/`userId`/`initials` 等身份属性，清除批注锚点并整体删除 `comments.xml` 及相关部件。**等价于「接受所有修订」，被删除的内容真的消失，会改变文档可见内容**；修订标记藏在页眉页脚、脚注、尾注里的也会一并处理 |
| 清理未引用媒体 | 两个层次：① 有关系但没有任何 XML 元素引用的图片部件（页眉删完常剩一堆）；② 从 `_rels/.rels` 出发不可达的 zip 条目（例如 `customXml` 留下的 `itemProps`），并剪掉 `[Content_Types].xml` 里指向已删部件的 Override |
| 删除匹配哈希图片 | 扫描正文、页眉、页脚、脚注、尾注中的图片，哈希命中就移除承载它的整个图形元素（DrawingML 的 `w:drawing` 或 VML 的 `shape`），并删除对应图片部件与关系。可用重复参数或清单文件一次给多个哈希 |

哈希输入会按算法校验长度（MD5 32 位 / SHA1 40 位 / SHA256 64 位十六进制），大小写不敏感；多个哈希可用逗号、分号、空格或换行分隔。

## 文件名正则重命名

- 作用范围只有**主文件名**，`.docx` 扩展名原样保留，不会被正则改掉。
- 匹配上才动：没匹配、或替换后和原来一样的文件保持原样。
- 必须先出计划再执行：重名判断要跨文件看，所以 GUI 走「预览 → 勾选 → 应用」，CLI 建议先 `-n` 干跑。
- 这些情况会被拦下、在预览里标红跳过：**目标文件已存在**、**与本批次其他文件重名**、**替换后为空**、**含 Windows 非法字符**（`\ / : * ? " < > |`）、**以空格或句点结尾**、**撞上 CON / NUL 这类保留名**。
- 链式改名（A→B、B→C，两个文件都在同一批）执行顺序敏感，一律判冲突跳过，需要分两批做。
- 只改文件名，不打开也不修改文档内容。和内容清理同时使用时，顺序是**先清理内容、再改名字**，清理失败的文件不会被改名。

### 正则怎么写（语法速查）

| 想做的事 | 写法 | 说明 |
| --- | --- | --- |
| 删掉空格 | ` `（一个空格）或 `\s` | 单个空格是合法规则，直接填就行；`\s` 还包含制表符和全角空格 |
| 删掉加号 | `\+` 或 `[+]` | `+` 是量词，**必须转义**或放进方括号，直接写 `+` 会报“正则无效” |
| 删掉加号和空格（成串一起删） | `[+\s]+` 或 `[+\s＋]+` | 末位 `+` 表示“前面的字符类连续出现一次以上”，连成一串一次删完；`＋` 是全角加号 |
| 只删开头几个空格 | `^\s+` | `^` 锚定主文件名开头 |
| 只删末尾的标注 | `\s*\(\d+\)$` | `$` 锚定结尾，`\d+` 是一位以上数字，`\(` `\)` 是字面圆括号 |
| 删掉【复印件】这种固定文字 | `【复印件】` | 中文括号在正则里不是元字符，不用转义 |
| 保留一部分内容 | `(.+?)_v\d+` + 替换 `$1` | `(...)` 捕获分组，替换模板里用 `$1` 引用第 1 组 |

元字符一共这些：`. ^ $ * + ? ( ) [ ] { } \ |`。**想匹配它们本身，在前面加反斜杠**，或者整段塞进 `[...]` 里（方括号内的 `+ * ? .` 都是字面字符）。星号 `*`、问号 `?` 也只当量词用，单独写同样会报错。

## 水印 / 来源检测

用来清掉文档里的**来源品牌水印与隐形追踪图片**——常见于从各类文档分享站点下载的 `.docx`。触发词完全由使用者自己提供，程序不预置任何品牌词，也只处理使用者有权处理的文档。**两种行为截然不同，默认是安全的那种**：

| 模式 | 触发条件 | 删什么 | 开关 |
| --- | --- | --- | --- |
| 精准（默认） | 文档里出现触发词 | 只删水印对象：VML 艺术字、`descr`/`alt` 带关键词的 logo 图、≤2pt 的埋点图，以及**命中文字本身**（正文里出现也删） | `--watermark` |
| 激进 | 同上 | 上面的都做，再删掉文档内**所有**图片 | 再加 `--wm-drop-all-images` |

为什么默认不删全部图片：实测一份 500 多张图的试卷文档，里面近 900 处图引用全是题目插图（装置图、方程式、图表），真正的水印对象只有个位数。全删等于把文档毁掉。

### 它认哪些痕迹

处理分两步走，**顺序是先清水印、再问图片**——这样 OCR 不必去认那些马上要被删掉的 logo，判断的也是「清完水印后剩下的图」（日志里会打出「已先清水印对象 N 处…接下来只识别剩下的图片」）。

**第一步：清掉水印对象和命中文字**

1. **VML 艺术字水印**：`w:pict` 里的 `v:shape`，文字藏在 `alt` 属性或 `v:textpath/@string` 里（页眉页脚里的「××公司 版权所有」就是这种），`id` 形如 `PowerPlusWaterMarkObject…`。
2. **成组水印**：`v:group alt="品牌词"` 包一个 `v:shape`，只删子形状会留下带 `alt` 的空组，所以连空 `v:group` / `w:pict` 一起清。
3. **DrawingML logo 图**：`wp:inline` 里的图片，`wp:docPr/@descr` 或 `pic:cNvPr/@descr` 写着品牌词（Word 里叫「替换文字」，看不见但跟着图走）。
4. **隐形埋点图**：`width:.05pt;height:.05pt` / `0.75pt` 这种尺寸的图，正常插图不可能这么小，一律当埋点删掉。
5. **命中文字**：正文、页眉、页脚、脚注、尾注里出现的关键词，**只删关键词这几个字**，同段其他文字保留（「本题由某某网整理」→「本题由整理」）。跨 run 拆开写的（`某公`+`司`）也能删——按整段拼起来定位再逐字回写。所以正文里真的出现触发词也会被清掉。

**第二步：图片里的文字（可选，给 `--ocr` 才做）**

### OCR 怎么用

`--ocr <目录>` 指向本机 `ppocr.exe` 所在目录（PaddleOCR 编译版，需要同目录下有 `models\`）。程序会：

1. 把**上一步清完水印之后剩下的**位图抽到系统临时目录（emf/wmf/svg 读不了，跳过；小于 2KB 的多半是 1×1 埋点图，也跳过）；
2. **一次进程跑完整个目录**——单张调用每次都要重新加载模型（约 5 秒），批量才是可用速度；
3. 把识别到触发词的图片按关系 ID 删掉，其余不动；
4. 删临时目录。

实测 20 张位图约 14 秒（含模型加载）。默认每个文档最多识别 60 张，`--ocr-max 0` 解除限制；识别失败或超时只报警告，不影响文档本身。

### 注意

- `--watermark` 只在**命中时**动手：没检出触发词的文件一个字节都不会改，日志是 `[跳过] 未检出指定文字，图片未动`。
- 加 `-n` 干跑会**真扫一遍**并告诉你命中在哪、本来会删多少（和实跑同一套判定，数字一致），但不动文件：
  `[干跑] 命中，将删除水印图形 4 处、命中文字 1 处；命中：页眉shape/@alt「某公司 example.com」…`。干跑不跑 OCR。
- **命中文字会真的从文档里消失**（正文也一样），这是不可逆的内容改动。触发词别写太短——写短片段会把长 URL 削得残缺不全，建议直接用完整的品牌词。
- 和 `--headers` 一起用没意义：页眉页脚整个删了，水印自然也没了，但要清正文里的水印请单用 `--watermark`。
- 水印检测**不在 `--all` 里**：它会改变可见内容，必须显式要。
- 跑完建议 `--validate` 确认校验错误数没增加（批量时看退出码）。

## 写入方式

每个文件都这样处理，全程不产生备份文件：

1. **预检**：只读属性、被 Word 占用（独占打开失败）的文件直接报 `[异常]` 跳过，不做任何改动。
2. **读入内存**：同时用内存副本跑一次 OpenXmlValidator，得到原文档的错误数基线（原文档本身有错也照常处理，比较的是「有没有变差」）。
3. **在临时文件上改**：同目录的 `.<原文件名>.wtmp`，改完关掉包。
4. **再校验**：错误数比基线多就放弃，删掉临时文件，原文件不动；没有变化（全部 `[跳过]`）也直接删临时文件，不重写原文件。
5. **原子替换**：`File.Replace` 覆盖原文件，替换失败同样保留原文件。

## 已知限制

- 只支持 `.docx`：`.doc`/`.xls` 是二进制格式无法处理，`.docm`/`.dotx` 尚未放开，`.pptx`/`.xlsx` 的清理逻辑与 Word 不通用。完整的格式边界与扩展计划见 [FORMAT-SPEC.md](FORMAT-SPEC.md)。
- 直接修改原文件，无备份、无撤销（但写入失败时原文件不会被改动）。
- 「删除末尾空白节」只动空白节，不碰任何有内容的节；要给某个文档强制删掉最后一节（含正文），加 `--force`。
- 末尾连续的空段落不会被顺带删掉——空段落往往用来占位或留白，程序不去判断。删完节后想进一步压掉空白，请手工处理。
- 图片删除覆盖内嵌图、浮动图和 VML 图片；形状填充、图表里的图片不受影响。
- 同一批哈希在文档中的所有出现位置都会被清除；计算和匹配必须使用同一种哈希算法。
- 隐私清理只摘外部超链接的指向，文字和格式保留；域代码、书签不在此项范围内。批注与修订痕迹由 `--track-changes` 单独处理。
- 「接受修订、清除批注」会改变文档可见内容：`ins` 的内容保留、`del` 的内容真的消失，相当于在 Word 里点了「接受所有修订」。请先 `--dry-run` 或用副本确认。
- 未引用媒体清理会把包内不可达的条目一并删除，这属于 OPC 允许的清理，但会让文件比"只删页眉页脚"更彻底地变小。
- 重命名只作用于主文件名，`.docx` 扩展名不受正则影响，不会被改成别的后缀。
- 链式改名（A→B、B→C，两个文件在同一批）会判为冲突跳过，请分两批执行。
- 重命名同样就地生效、没有撤销，先用 `--dry-run`（CLI）或预览对话框（GUI）确认。

## 构建

需要 .NET 8 SDK。

```powershell
# 编译（框架依赖，输出 bin\Release\net8.0-windows\win-x64\DocxToolbox.exe）
dotnet build .\DocxToolbox.csproj -c Release -r win-x64

# 发布单文件版（约 6.99 MB，目标机需安装 .NET 8 Desktop Runtime）
dotnet publish .\DocxToolbox.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true

# 发布产物不会自动出现在根目录，需要手动复制
Copy-Item '.\bin\Release\net8.0-windows\win-x64\publish\DocxToolbox.exe' '.\Word 批处理工具箱.exe' -Force
```

项目结构见 [AGENTS.md](AGENTS.md)。
